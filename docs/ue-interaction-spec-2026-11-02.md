## §0 输入与实测证据

### 0.1 引用前置勘察（不重复统计）

本次不重新统计代码量。以下事实直接采信，作为全文的约束前提：

- 86 个 .vue 中 24 用 `van-dialog`、10 用 `van-popup`、12 含 `van-picker`（16 处）；**8 个文件把 picker 内联塞进 `#input` 插槽**（equipment 2 / wms 3 / quality 3 / production 1）。
- 内联 `style="` 333 处；仅 30/86 文件有 `<style>` 块；无统一 Dialog 封装。
- `:hover` 28 处（MainLayout 9 处）；`@touchstart` / `touch-action` / `pointerdown` / `overscroll-behavior` / 44px 最小热区约束 **全部为 0**；`@media` 全站 6 处。
- 7 处已失效的 Tailwind 类名（项目未装 Tailwind，类不生效且无报错）。
- 已有正确范式：`components/SelectField.vue`（readonly field + 底部浮层 picker，已全局注册）、`pages/basics/` 8 个页面、`AdvancedSearchPanel` / `ListRowDetail` / `usePagination`。

### 0.2 本次实测证据（新采集，供全文引用）

对 https://mfg1.ziwi.cn 以两个触屏视口实测（截图见 `docs/ue-evidence/`）：

| 指标 | 手持 412×915（竖屏） | 工位机 1024×768 |
|---|---|---|
| 「新建维护计划」弹窗宽×高 | 320×658（占屏高 72%） | 320×658（占屏高 86%） |
| 弹窗内内联 picker 高度 | 308 | 308 |
| 弹窗内同语义确认按钮 | **4 个**（picker 取消/确认 + dialog 取消/确认） | 4 个 |
| 报工表单字段数 / 分组数 | 14 / 6 | 14 / 6 |
| 单个内联 picker 字段高度 | 352（一屏仅能看约 2 个字段） | 328 |
| 产品列表：容器可视宽 vs 表格实际宽 | 172 vs 900（可见 19%） | 784 vs 900 |
| 列表行内操作按钮尺寸 | 22×24 | 22×24 |
| 侧边栏占宽 | 200（占屏宽 48.5%） | 200 |

三张关键证据：`ue-evidence/handheld-412x915--maintenance-plans-dialog.png`、`handheld-412x915--products.png`、`handheld-412x915--work-report-form.png`。

**由此得出本文的三条底层判断**：

1. 现有界面是「桌面宽屏 + 鼠标悬停」的交互假设被直接搬到触屏上，不是"样式不好看"的问题，是**交互模型不匹配**。
2. 塌陷的根因不是某个组件用错，而是**缺少"容器职责"约束**：内层组件可以撑开外层、外层可以无视视口、同一语义可以出现两组按钮。这类问题会以不同面貌在 21 个模块反复出现 —— 所以本文给出的是**规则**，不是修 8 个文件。
3. 车间场景的第一性能指标是**单手一次做对**，不是"信息全"。所有决策向"减少输入次数、放大可点区域、明确结果回执"让步。

## §1 用户与环境画像

### 1.1 物理条件矩阵

| 角色 | 典型设备 | 姿态 / 屏幕距离 | 手部条件 | 环境 | 一天最高频的 3 个动作 |
|---|---|---|---|---|---|
| 操作工 | 工位一体机（21.5" 立式，站立）；部分配手持 PDA | 站立，距屏 50–80cm，屏幕偏低或偏侧 | 棉纱/防割手套（电容触摸易失效）、手上有油污 | 机床旁，噪音高、粉尘/油雾、顶光或侧光反射 | ① 扫工单开工 ② 报工（合格数/不良数）③ 看本工位当前工单与节拍 |
| 班组长 | 手持 PDA / 平板 | 站立、单手持，距屏 30–40cm | 常戴手套；戴手套时只用拇指 | 走动中，光线变化大（车间↔过道） | ① 巡视工单进度 ② 处理安灯呼叫 ③ 代报工/校正报工 |
| 质检员 | 平板 10" + 手持 | 站立或半蹲，距屏 30–50cm | 防静电指套（薄，可触摸）或裸手 | 检验区，台灯/自然光混合 | ① 扫码调检验单 ② 逐项录实测值/判定 ③ 判不合格并转 NCR |
| 仓管 | 手持 PDA（带扫码枪）+ 工位机 | 站立/走动，距屏 30cm | 手套 + 搬运（常单手） | 仓库，光照弱、货架遮挡 | ① 扫单拣货 ② 扫批次发料 ③ 查即时库存 |
| 设备员 | 手持 PDA / 平板 | 蹲/趴/站立，距屏 20–50cm | 油污手套，常单膝跪地 | 设备旁，噪音高、油污、狭小空间 | ① 扫设备码看保养任务 ② 点检项逐项确认 ③ 报修/停机上报 |
| 调度/计划员 | 办公 PC 宽屏 | 坐姿，键盘鼠标 | 裸手 | 办公室 | ① 排产调整 ② 工单下达 ③ 异常工单追查 |
| 车间管理/厂长 | 大屏（不可触摸，只读） | 3–8m 远视 | — | 车间高光环境 | ① 看产量/达成率 ② 看安灯 ③ 看设备状态 |

### 1.2 由画像直接推出的设计含义

| 观察 | 设计含义（本文后续章节据此展开） |
|---|---|
| 手套是常态，电容屏会失灵 | 必须提供「手套模式」：热区放大一档、允许长按、以点选/扫码替代精细拖拽；关键动作必须有**扫码或刷卡兜底**，不能只有软键盘输入 |
| 单手操作占比高 | 主操作固定在屏幕下 1/3 拇指区；不使用需要双手配合的交互（拖拽排序、双指缩放、边缘滑入） |
| 屏幕距离 30–80cm，非 30cm 桌面距离 | 一屏信息量按"3 米外能辨认主数据"设计：主数据字重、单位、状态置顶；细节下钻 |
| 环境光强、反光 | 不依赖低对比度细节传递信息；状态不能只用颜色（必须颜色 + 文字/图标双编码） |
| 噪音高 | 声音反馈不可作为唯一反馈；所有结果必须有视觉回执 |
| 手上有油污 | 点击精度下降 → 相邻可点元素间距、禁用"小图标紧挨小图标"（现状 22×24 的操作列是反面案例） |
| 走动中操作 | 页面状态必须可恢复：切走/锁屏/误触返回后，已填内容不丢 |

## §2 任务模型（4 条核心任务流）

### 2.1 T1 报工（操作工 / 班组长代报）— 最高频

| 阶段 | 现状（实测） | 目标 |
|---|---|---|
| 入口 | 侧边栏 → 生产管理 → 报工管理 → 新增（**4 次导航**，手持屏侧边栏占 48.5% 宽） | 扫码直达（工单码/工位码），或「我的工单」列表一键进入 |
| 步数 | 14 个字段、6 个分组、1 次内联 picker（占 352px） | **3–5 步** |
| 输入方式 | 工单选滚轮（文字被截断）、工序编码手填、工序名称手填、起止时间手填、工时手填、工价手填 | 工单：扫码/点选；工序/产品/工价/工时：**自动带出**；数量：大数字键盘；不良：多选标签 |
| 完成标志 | toast「报工提交成功」后跳列表（无单号、无数量回执） | 回执卡：**报工单号 + 工单号 + 合格数 + 提交时间**，可"继续报下一单" |
| 触屏成本过高步骤 | ① 工单滚轮选择（列表可达百条）② 手填工序编码/名称 ③ 手填起止时间（应默认当前时间）④ 手填工时/工价（应带默认值） | ①②③④ 全部收敛为默认值 + 可改 |

### 2.2 T2 检验（质检员）

| 阶段 | 现状 | 目标 |
|---|---|---|
| 入口 | 品质管理 → 新建检验（仅"检验类型 + 备注"2 个字段） | 扫批次码/流转卡 → 直接进入对应检验单执行页 |
| 步数 | 建单 3 步；**执行录入路径当前不可达**（列表→详情→判定，实测需多次跳转） | 建单 2 步；执行 = 扫码 1 + 逐项录 N 项 + 判定 1 + 提交 1 |
| 输入方式 | 单选类型、备注文本 | 每检验项一行：合格/不合格二值大按钮 + 实测值数字键（仅计量项）；键盘不因切项收起 |
| 完成标志 | 跳列表，无判定结果展示 | 状态位即时变更（待检→已判定）+ 不合格自动给出「转 NCR」下一步 |
| 触屏成本过高步骤 | 逐项录入在 412 宽屏上需反复上下滚动；判定入口与数据不在同一屏 | 逐项卡片 + 自动聚焦下一项 + 底部固定"提交判定" |

### 2.3 T3 领料出库（仓管 / 操作工领料）

| 阶段 | 现状 | 目标 |
|---|---|---|
| 入口 | 仓储 → 出库单管理 → 列表行展开（只读明细）→ 无执行入口 | 扫出库单码 → 直接进入"逐行发料"执行页 |
| 步数 | 无执行路径；需先建单再另行操作 | 扫单 1 + 逐行扫码 N + 确认 1 |
| 输入方式 | 列表 + 高级检索（对仓管无用） | **连续扫码**为主：扫物料码→自动定位行→实发数默认=需求数→差异才改→自动跳下一行 |
| 完成标志 | 单据状态文字 | 逐行「已发」累计至等于「需求」→ 单据状态即时切为"已完成"，并给出差异摘要 |
| 触屏成本过高步骤 | 手动在长列表中找物料行；无扫码入口；行内 22×24 图标按钮 | 扫码头常驻、行自动定位并高亮、行内不再放小图标 |

### 2.4 T4 设备点检 / 保养（设备员）

| 阶段 | 现状 | 目标 |
|---|---|---|
| 入口 | 设备管理 → 保养任务（列表 + 新建弹窗，弹窗含内联 picker） | 扫设备码 → 该设备待执行任务（0 条则给空态与"新建"） |
| 步数 | 新建任务 5 字段弹窗（塌陷）；**"执行点检"路径缺失** | 扫码 1 + 逐项确认 N + 提交 1 |
| 输入方式 | 设备滚轮、任务类型自由文本、描述文本、优先级数字 | 项级三态（正常 / 异常 / 不适用）+ 异常时输入描述/拍照 |
| 完成标志 | toast | 任务完成态 + 异常自动挂起并提示"已生成安灯/报修"（交互衔接，功能侧确认） |
| 触屏成本过高步骤 | 自由文本"任务类型"（应枚举）；"优先级"数字（应三档语义）；无执行路径 | 全部枚举化；执行页优先于配置页 |

> **注**：T2/T3/T4 中标"路径缺失/不可达"的，属于**任务模型缺口**而非交互缺陷，需功能侧确认是否在本次改造范围（见 §10-Q3）。

### 2.5 任务流的通用形态要求

| 要求 | 说明 |
|---|---|
| 单任务单屏完成 | 一个任务流原则上不跨页超过 2 屏；必须跨页时保留"当前位置/剩余步数"提示 |
| 扫码优先于选择，选择优先于输入 | 输入是最后手段。凡有唯一编码的实体，优先扫码；凡枚举 ≤ 20 项，用点选不用键盘；凡 > 20 项，用"搜索 + 列表"不用滚轮 |
| 默认值必须可解释 | 自动带出的值要能被用户看懂来源（如"合格数=投入数-不良数"），避免"黑箱默认值"被误提交 |
| 完成必须可核对 | 提交类动作的结束态是一张**回执**（单号 + 关键数量 + 时间），不是一行 toast |

## §3 双端形态决策

### 3.1 三种运行形态（Form Factor）

| 标记 | 判定条件 | 典型设备 |
|---|---|---|
| **W** 宽屏 | 视口宽 ≥ 1024 且横屏 | 工位一体机 21.5"/24"、办公 PC |
| **T** 中屏 | 600 ≤ 视口宽 < 1024，或宽度 ≥1024 但为纯触屏（无悬停） | 10" 平板、横置手持大屏机 |
| **H** 手持 | 视口宽 < 600，或竖屏且宽 < 768 | PDA、扫码手机、5–6" 工业手持机 |

判定规则（实现层）：

1. **主判据是宽度**，因为宽度直接决定"一屏能容纳几个并列信息单元"。
2. **增强判据是输入能力**：仅当 `hover` 可用且指针精确时，才允许出现悬停态与密集小控件；纯触屏形态下所有"只能靠悬停才能看到的信息"视为丢失。
3. **不做"设备嗅探"**：同一 URL 同一套逻辑，仅形态分支；手持机横竖屏切换必须能即时重排，不得要求刷新。

### 3.2 元素形态决策表（哪些必须不同 / 必须一致）

| 元素 | W 宽屏 | T 中屏 | H 手持 | 判定 |
|---|---|---|---|---|
| 新建/编辑表单 | 居中浮层，宽度按视口比例上限，内容整体滚动 | 右侧抽屉（近全宽）或半屏浮层 | **全屏页**，底部固定主操作 | 必须不同 |
| 枚举选择器 | 下拉浮层 + 可选搜索 | 底部浮层 + 搜索框 + 列表 | 底部浮层 + 大行高列表（>8 项强制带搜索） | 必须不同（但"点击后弹浮层"必须一致） |
| 数据列表 | 表格，首列冻结，允许横向滚动且**必须显性提示** | 表格减列（保留 3–4 列）+ 行展开补细节 | 卡片流（主标识 + 状态 + 关键数值 + 时间） | 必须不同 |
| 详情 | 右侧抽屉或双栏 | 全屏页 | 全屏页，主操作固定底部 | 必须不同 |
| 危险确认（删除/红冲/作废） | 居中确认浮层 | 底部确认浮层 | 全屏确认页 | 必须不同 |
| 筛选/高级检索 | 常驻筛选栏 | 折叠面板 | 底部浮层，条件以标签回显 | 必须不同 |
| 交互动效的功能与体感档位 | — | — | — | **必须一致**（§7） |
| 术语、字段标签、字段顺序与分组 | — | — | — | **必须一致**（§8） |
| 状态语义与其文字表述 | — | — | — | **必须一致** |
| 校验文案措辞格式 | — | — | — | **必须一致** |
| 提交结果回执的内容结构 | — | — | — | **必须一致** |
| 返回行为（不丢草稿） | — | — | — | **必须一致** |
| 空态/错误态的四分类 | — | — | — | **必须一致** |

### 3.3 五条容器级硬约束（本次塌陷的直接对策，适用于全部 21 个模块）

| 编号 | 约束 | 违反后果（已发生） |
|---|---|---|
| **R1** | 浮层/抽屉内若需滚动，**浮层自身是唯一滚动容器**；选择器只允许出现在底部浮层或全屏页，**任何情况下不得内联进表单流** | 308px picker 撑爆 320px 弹窗，4 个字段被挤出屏 |
| **R2** | 浮层宽度由外层策略决定（视口比例 + 上限），**不得由内容撑开** | 内层 picker 决定外层宽度；`!w-[500px]` 类失效后无人察觉 |
| **R3** | 一个语义只允许一组操作按钮；内层组件自带确认时，外层不再提供同语义按钮 | picker 与 dialog 双"取消/确认"并排 |
| **R4** | 主操作必须常驻拇指可达区（H/T 形态固定底部），不随内容滚出 | 提交按钮在 14 字段表单末尾 |
| **R5** | 悬停只作增强，不得承载唯一信息 | 28 处 hover 在触屏零生效；失效的 Tailwind 类零报错 |

> R1–R5 是本文对架构侧的**唯一强制接口**：建议以"表单容器 / 浮层容器 / 选择器"三个受控组件承载，业务页不再自行组合 van-dialog + van-picker。

## §4 信息组织原则

### 4.1 表单分组与规模上限

| 规则 | 上限 | 超标处理 |
|---|---|---|
| 单个表单可见字段 | ≤ **8** 个（不含隐藏默认值） | 拆分为「必填核心区」+「更多信息（默认折叠）」 |
| 单个分组字段数 | ≤ **5** | 拆分组，或改组内用两列（仅 W 形态） |
| 分组数 | ≤ **3** | 合并语义相近组 |
| 必填字段 | ≤ **4**（超出说明模型设计有问题） | 通过扫码/默认值消除手填 |
| 单屏可见必填项 | ≥ 全部必填（H 形态一屏内） | 分步（Step 1/2），带剩余步数 |

现状对照：报工表单 14 字段 / 6 分组 / 必填 2 项 —— 字段量与分组量均超标 1.75 倍，且可默认值的字段占 6 个。

### 4.2 长文本与编码类字段

| 类型 | 示例 | 展示规则 |
|---|---|---|
| 实体编码 | `EQ-B1-11012316`、`WO-20261102-0012` | 等宽字体、**单行不换行**、超长中间省略（保留首尾）、点击可展开全文并一键复制、扫码时整串高亮 |
| 长名称 | `E2E_BROWSER_MAT_1783837596368 - E2E_BROWSER_测试物料` | 名称优先、编码作副行；列表行最多 2 行，超出省略并可展开 |
| 自由备注 | 异常描述 | 多行文本框，H 形态 ≥3 行高；不在列表行内展开显示，仅显示"有备注"标记 |
| 数值 + 单位 | `300 PCS`、`120 件` | 数值与单位**同行右对齐**，单位不进入输入框（避免"300件"被当数字解析失败） |
| 时间 | 2026-11-02 14:23 | 列表显示"今天 14:23 / 昨天 / 2026-10-30"三档；详情显示完整 |

### 4.3 列表行的信息层级

每一行固定四段，顺序不可变：

1. **主标识**（单据号 / 物料编码）
2. **状态**（标签 + 文字，不只靠颜色）
3. **关键数值**（数量 / 达成 / 差异，最多 2 个）
4. **时间**（最近变更）

辅助信息（仓库名、来源单号、规格、备注标记）在 H 形态默认收起，行展开看；W/T 形态可作为副行展示。理由：实测手持屏内容区仅 172px 宽，任何并列信息都会挤掉主标识。

### 4.4 详情的"三明治"结构

详情页首屏自上而下固定三层：**是什么（标识 + 状态）→ 什么情况（关键指标/进度）→ 下一步能做什么（唯一主操作 + 次级操作折叠）**。禁止把操作按钮散落在多个滚动位置。

## §5 状态与反馈体系（本方案最重要章节）

### 5.1 七种状态的统一规范

| 状态 | 用户看到什么 | 能做什么 | 如何恢复 / 结束 | 明确禁止 |
|---|---|---|---|---|
| **加载中** | 骨架占位，**保持最终布局尺寸**（不出现居中转圈把内容挤走）；列表首屏 3 行骨架；分页在列表底部行内提示 | 可继续滚动已加载部分；可返回 | 加载完成原位替换；失败转"失败态"带"重试" | 全屏遮罩断流（登录/首次进入除外）；加载引起布局跳动 |
| **空** | 必须区分四类，文案与动作不同：①真无数据（说明 + 主操作"新建第一个…"）②筛选无结果（回显当前条件 + "清空条件"）③无权限/无数据范围（"当前仅显示本班组数据" + 联系管理员）④加载失败（"加载失败" + 重试） | 对应单一动作 | 清空条件 / 新建 / 重试 | 全部统一成"暂无数据"（现状 `van-empty` 单文案即为反例） |
| **校验失败** | ①提交时：顶部错误摘要（N 项待修正，可点跳）②页面自动滚动到**第一个错误字段**③该字段高亮 + 就近显示原因 ④焦点落入该字段并唤起对应键盘 | 就地修改，不必重新提交整表 | 修正后该行错误即时消除 | 只用 toast 报错（现状 `showToast('请选择设备并填写计划名称')` 即反例：不定位、3 秒消失、两个字段合一句） |
| **保存成功** | **回执卡**：单号（可复制）、关键数量、时间、下一状态；两个动作"继续新建/查看单据"；返回列表后该行高亮并滚动到可见 | 继续 / 查看 / 返回 | 明确结束点，不留悬念 | 仅一行 toast；toast 未消失就自动跳页 |
| **网络离线 / 弱网** | 顶部常驻条（不遮挡操作区）显示"离线 · N 条待提交"；提交失败时**区分网络失败与业务失败** | 查看待提交队列、重试、删除待提交 | 网络恢复自动补交并给出结果；业务失败需人工处理 | 把网络超时提示成"提交失败"（用户会重复提交）；高风险操作（作废/红冲/删除）在离线态仍可点 |
| **无权限** | 页面级：403 页说明 + 所需权限码（可复制给管理员）+ 返回。按钮级：**禁用 + 说明原因**，不静默消失 | 复制权限码、返回、切换到有权限的同类视图 | 由管理员授权后刷新即恢复 | 静默隐藏高频按钮（用户以为功能不存在）；整页白屏 |
| **危险操作** | 二次确认，必须**重述后果与影响对象**（"作废后不可恢复，当前在制 30 件将回退"）；按风险分两档确认方式：中风险=明确按钮，高风险=长按至进度环闭合 或 输入单据号后 4 位 | 取消（默认焦点、且不与主操作同位置）/ 确认 | 完成后必须留下可回溯痕迹（操作记录入口） | 确认按钮与主操作同色同位；"确定/取消"文案无语义（应为"确认作废 / 再想想"） |

### 5.2 反馈的"三秒可判"原则

任何一次操作结束后，用户必须能在**不做任何额外点击**的情况下回答三个问题：**成功了吗？成功了什么？下一步去哪？** 现状多数页面只回答了第一个（toast），第二三个靠猜。

### 5.3 反馈载体选择表

| 场景 | 载体 | 理由 |
|---|---|---|
| 轻量、无需确认、不改变数据 | 行内短暂提示（toast） | 不打断 |
| 改变数据、需要单号/数量核对 | 回执卡（页面内或底部浮层） | 车间需要可核对凭证，且常被拍照留档 |
| 需要用户决策（冲突/风险/取舍） | 确认浮层（H 形态为全屏确认页） | 需要空间说明后果 |
| 持续性系统状态（离线、待提交数） | 顶部常驻条 | 不能靠瞬时提示表达持续状态 |
| 字段级问题 | 字段就近提示 + 顶部摘要 | 触屏上"滚回去找"成本极高 |

## §6 触屏人因规范

### 6.1 尺寸与间距

| 项 | 裸手 | 戴手套（手套模式） |
|---|---|---|
| 最小可点热区 | **48×48** | **56×56** |
| 列表行最小高 | **48**（推荐 52–56） | **56**（推荐 64） |
| 输入框可点高度 | **48** | **56** |
| 底部主操作条高度 | 56 | 64（含安全区留白） |
| 危险操作热区 | 56 | **64** |
| 同组相邻可点元素间距 | 8 | 12 |
| 不同语义可点元素间距 | 24 | 24 |
| 浮层关闭按钮热区 | 48 | 56 |

现状对照：列表行内操作按钮 22×24（实测），约为手套标准的 1/6 面积；顶部图标（AI 助手/退出）与页面标签关闭"×"同属小热区密集区。

### 6.2 允许 / 禁止的手势

| 手势 | 结论 | 约束 |
|---|---|---|
| 单击（tap） | 允许 | 唯一主要交互 |
| 纵向滚动 | 允许 | 惯性滚动保留；滚动容器不得嵌套（R1） |
| 横向滑动 | 限制允许 | 仅用于同级视图切换（tab）与列表行左右操作；**不得用于切换主流程步骤** |
| 下拉刷新 | 允许（列表页） | 需有明确阈值提示，防误触 |
| 长按 | 限制允许 | 仅两种用途：进入多选模式、高风险操作确认；必须有进度反馈（进度环闭合），松手即取消 |
| 滑动删除 | **禁止** | 车间误触率高，且无法撤销 |
| 拖拽排序 | **禁止**（手持/平板） | W 形态可保留但必须提供"上移/下移"替代操作 |
| 双指缩放 | **禁止** | 已通过 viewport 禁用，保持 |
| 边缘滑入返回 | **禁止** | 与系统手势冲突；返回只走显式返回按钮 |
| 悬停 | **禁止承载信息** | 仅作增强 |

### 6.3 防误触规则

| 风险 | 规则 |
|---|---|
| 重复提交 | 提交后按钮立即进入"提交中/已提交"锁定态；同一单据在结果返回前不接受第二次提交；服务端需幂等（前端不承担唯一防线） |
| 误滑关闭 | 含未保存数据的浮层/抽屉**禁止下滑关闭**；点击遮罩关闭时二次确认或直接禁用遮罩关闭 |
| 误触删除 | 删除不与"展开/编辑"相邻；间距 ≥24；二次确认中"取消"为默认焦点 |
| 误触切换 | 底部 tab / 状态 tab 切换不丢当前筛选条件；切换前若有未保存内容需提示 |
| 连击 | 同一元素连续 2 次点击在同一响应周期内视为 1 次（除明确"下一项"按钮） |
| 手套模式 | 全局开关（按设备记忆），开启后所有热区按手套档；对"操作工/仓管/设备员"角色默认开启 |

## §7 动效的信息功能定义

> 本章只定义**动效承担什么信息**与**体感档位**（瞬时 / 快速 / 常规 / 舒缓）。具体时长、缓动曲线、位移距离属于 UI 阶段，本文不规定。

### 7.1 触屏为什么更需要动效

触屏没有指针悬停、没有光标位置、没有右键菜单，物理按键的"按下感"也消失了。**动效在触屏上不是装饰，是唯一的"手感"来源**——它代替了鼠标的悬停与指针，回答"我这一下有没有点到、点到了什么、接下来发生了什么"。

### 7.2 八类信息功能

| 编号 | 信息功能 | 传递的内容 | 体感档位 | 出现场景 | 必须避免 |
|---|---|---|---|---|---|
| A1 | **按下已注册** | "这一次触摸被系统收到了" | **瞬时**（低于感知延迟门槛，用户不觉得有等待） | 任何可点元素被按下即刻；含禁用态（禁用要有"按了但无效"的区分） | 无反馈（用户会连点，导致重复提交） |
| A2 | **操作已生效（结果确认）** | "这件事成了" | **快速** | 提交成功、状态标签变更、数量累加 | 用长动画庆祝；成功动画阻塞下一次操作 |
| A3 | **层级关系** | "这层浮在上面/这层是从这里出来的" | **常规** | 浮层/抽屉/全屏页进出；弹出方向必须与来源位置相关（从底部弹出 → 从底部进入） | 无来处的淡入；层级不明导致用户误以为跳页 |
| A4 | **方向与进度** | "我在第几步、往哪个方向走" | **常规** | 分步表单前进/后退、向导切换、列表定位到目标行 | 前进后退用同方向动画（用户分不清是进是退） |
| A5 | **等待中（时长感知）** | "还在处理，别急，不是卡死" | **舒缓**（循环，节奏平稳不焦躁） | 超过即时响应预期的请求、扫码识别中、批量提交 | 用等待动画掩盖长耗时却不给进度；加载动画引发布局跳动 |
| A6 | **注意力引导** | "看这里" | **快速**（一次性） | 校验失败定位到字段、刚创建的行高亮、异常/安灯新条目 | 持续闪烁/呼吸（车间长时盯屏会疲劳）；多处同时引导 |
| A7 | **临界/危险预告** | "再往下就不可逆了" | **常规** | 长按进度环推进、滑动到删除阈值边缘 | 用动效诱导用户滑过危险阈值 |
| A8 | **空间连续性（列表↔详情）** | "我看的还是同一个东西" | **常规** | 列表行 → 详情返回时回到原滚动位置并高亮 | 返回后跳回列表顶部（车间用户会彻底迷路） |

### 7.3 动效纪律

| 纪律 | 说明 |
|---|---|
| **不阻塞** | 关键路径上的任何动效必须可被下一次触摸立即打断或跳过；动效不得成为提交前的等待 |
| **不承载唯一信息** | 任何信息不能只由动效表达（颜色/形状/文字必须同时具备），尊重"减少动态效果"的系统偏好时信息不得丢失 |
| **降级策略** | 低端手持机 / 省电模式 / 系统开启减少动效：保留 A1、A2、A6（必需反馈），A3/A4/A8 降为无位移的层级切换，A5 仅保留静态进度指示 |
| **频次守恒** | 每屏同一时刻的动效不超过 1 处主动引导；列表滚动中不触发任何入场动画（会与滚动争抢帧） |
| **一致性** | 同一信息功能在全部 21 个模块必须使用同一档位，不允许某模块"更活泼" |

## §8 一致性规则（跨 21 模块统一清单）

| 维度 | 统一规则 | 现状问题 |
|---|---|---|
| **术语** | 同一对象只有一种叫法。建议：**保养计划 / 保养任务**（"维护"与"保养"当前混用） | 文件名与菜单同时存在 MaintenancePlans「维护计划」与 MaintenanceTasks「保养任务」，语义边界不清；「报工管理」与「报工录入」并存 |
| **状态标签** | 状态码 → 文案 → 语义档（中性/进行/成功/警示/危险）集中一处维护，禁止页面内各自写字典 | 现状每页内联 `statusLabel` 映射（如出库单页），改一处漏九处 |
| **字段标签** | 名词 + 单位进标签（"周期值"、"重量(kg)"）；必填用统一标记；不写"请输入…"式标签 | 同义字段多种写法：设备 / 设备编码 / 机台；备注 / 描述 / 说明 |
| **字段顺序** | 固定：标识 → 归属（工单/设备/物料）→ 数值 → 时间 → 备注 → 状态 | 同一实体在不同页字段顺序不同 |
| **操作按钮位置** | 列表页主操作在右上；表单页主操作固定底部（H/T）/浮层右下（W）；破坏性操作永不出现在主操作区 | 现状主操作位置随页面变化（有的在顶部 padding 区，有的在表单末尾） |
| **列表默认排序** | 待处理优先（按状态权重）→ 最近变更倒序；排序规则在页面上可见 | 默认后端返回顺序，用户无法判断"最该处理的是哪条" |
| **分页 vs 加载更多** | 统一**加载更多**（全部形态），底部显示"已显示 N / 共 M"；不使用页码翻页 | 现状同时存在 `page` 分页与 `van-list` 加载更多两套（如保养任务 vs 出库单） |
| **返回行为** | 返回不丢已填内容（草稿本地保留）；返回目标为来源页并恢复滚动位置；H 形态下拉返回不作返回手势 | 现状多数页面 `router.back()` 后表单内容全丢；返回回列表顶部 |
| **浮层关闭** | 表单类禁止下滑关闭；含未保存内容时关闭需确认；点击遮罩的策略全站一致 | 现状不一致且无确认 |
| **空态/错误文案** | 四类空态模板 + 错误文案格式"字段/对象 + 问题 + 怎么改"，全站同一模板 | 全站多为单句"暂无数据"与"创建失败" |
| **数字与单位** | 输入框只装数字；单位在标签或右侧只读；数量展示不省略小数位规则需统一（建议最多 3 位） | 现状 `cycle_value` 与单位分离且单位可自由手填 `month/week`（未枚举） |
| **图标语义** | 展开/收起、编辑、更多、删除四个固定图标 + 文字兜底（H 形态必须带文字或足够大的热区） | 现状纯图标 + 22px 热区，仓库/手套场景不可用 |
| **权限门语义** | 菜单级：无权则不显示；页面级：403 说明页；按钮级：禁用 + 原因。同一权限码在三处语义一致 | 现状菜单过滤有回退放行逻辑（权限未加载时全放行），与按钮级拦截语义不一致 |

## §9 验收标准（可机械检查）

严重级别：**P0 = 红线**（不通过即整体验收不通过）、P1 = 必须、P2 = 建议。

### 9.1 五条红线（P0）

| 编号 | 检查项 | 判定方法（机械可验证） |
|---|---|---|
| UE-P0-01 | 选择器不得内联出现在表单流中 | 自动化遍历：DOM 中任一 `van-picker` 的祖先链包含 `van-field` 且其可见高度 > 120px → 违规 |
| UE-P0-02 | 任何可点元素最小热区 ≥ 48×48（手套模式 ≥ 56×56） | 脚本遍历所有 `button / a / [role=button] / .van-cell[clickable]`，取 `getBoundingClientRect()`，低于阈值输出选择器清单 |
| UE-P0-03 | 浮层内滚动不得带动背景滚动 | 打开浮层 → 在浮层内连续上滑到底后再滑 3 次 → 断言 `window.scrollY` / 背景列表 `scrollTop` 不变；并检查浮层打开时背景是否锁定 |
| UE-P0-04 | 同一屏不得出现两组同语义确认按钮 | 打开任一浮层，枚举所有按钮文案，若出现 ≥2 组 {"取消","确认"} 且分别属于不同容器 → 违规 |
| UE-P0-05 | 提交幂等：连续两次触发只产生一次有效请求 | 双击提交按钮，网络面板统计同一接口 POST 次数 = 1；且按钮在返回前处于锁定态 |

### 9.2 形态与布局（P1）

| 编号 | 检查项 | 判定方法 |
|---|---|---|
| UE-01 | 412×915 / 768×1024 / 1024×768 / 1440×900 四视口下无内容重叠、无裁切、无文字竖排 | 四视口逐页截图，人工/图像比对；重点检查顶栏标题是否被压缩换行 |
| UE-02 | 浮层宽度不与内层内容耦合 | 320 / 412 / 768 / 1024 四视口下测量浮层宽高，H 形态浮层宽 ≥ 视口 92% 或为全屏 |
| UE-03 | 表单页主操作在首屏可见或固定 | 打开表单，未滚动时主操作按钮 `top < viewportHeight`；或其为 `position: fixed` 底部条 |
| UE-04 | 400 宽下无非表格容器的横向溢出 | `document.scrollWidth <= innerWidth + 1` |
| UE-05 | 表格类容器必须显性提示可横向滚动 | 存在 `scrollWidth > clientWidth` 时必须存在滚动提示元素（渐变/箭头/文字） |
| UE-06 | 无悬停丢失信息 | 强制禁用 `:hover`（模拟触屏）后，逐页对比信息完整性，不得有仅悬停可见的内容 |
| UE-07 | 无失效样式类残留 | 全量扫描 class 属性，命中 `w-[`、`min-w-[`、`max-h-[`、`flex-1`、`space-y-` 等未安装框架的类名 → 违规 |
| UE-08 | 行高与输入高度达标 | 列表行 ≥48、输入框 ≥48（手套模式 56） |

### 9.3 状态与反馈（P1）

| 编号 | 检查项 | 判定方法 |
|---|---|---|
| UE-09 | 七种状态均有实现且可枚举 | 对每个列表页与表单页，用 mocking 构造：加载/空/筛选空/无权限/失败/成功/离线，逐一截图存档，缺失即不通过 |
| UE-10 | 校验失败必须定位 | 提交空必填表单 → 断言页面滚动到第一个错误字段（该字段 `top` 在视口内）且存在错误摘要 |
| UE-11 | 保存成功必须含单号与关键数量 | 断言成功态 DOM 中存在单据号文本（匹配单号正则）与数量 |
| UE-12 | 网络失败与业务失败文案必须不同 | 断网提交 vs 服务端 4xx 提交，两次提示文案与动作不同 |
| UE-13 | 危险操作二次确认且重述后果 | 触发删除/作废/红冲，断言确认文案包含被影响对象标识；取消为默认焦点 |
| UE-14 | 无权限按钮不静默消失 | 用无权限角色登录，断言目标按钮存在且 `disabled`，或存在明确说明 |

### 9.4 交互与动效（P2）

| 编号 | 检查项 | 判定方法 |
|---|---|---|
| UE-15 | 键盘类型正确 | 数量类字段唤起数字键盘、日期唤起日期选择、编码类优先扫码入口 |
| UE-16 | 返回不丢草稿 | 填 3 字段 → 返回 → 再进入，断言内容仍在（或明确提示已保存草稿） |
| UE-17 | 返回恢复滚动位置 | 长列表滚动到第 20 行 → 进详情 → 返回，断言滚动位置还原且该行高亮 |
| UE-18 | 无禁止手势 | 静态扫描不得出现滑动删除、拖拽排序（手持/平板）、双指手势监听 |
| UE-19 | 动效可打断且不阻塞 | 关键路径（提交、弹层出入）动画进行中立即点击下一目标，断言操作生效 |
| UE-20 | 减少动效偏好下信息不丢 | 系统开启"减少动态效果"，复核 A1/A2/A6 反馈仍存在 |
| UE-21 | 图表在 400 宽下可读 | 每个含 ECharts 的页面在 412 视口截图，坐标轴标签不重叠、无需横向滚动 |
| UE-22 | 手套模式可用 | 开启手套模式后 UE-P0-02 阈值升为 56×56 并通过 |

### 9.5 验收执行方式

1. **自动化**：UE-P0-01~05、UE-01~08、UE-15、UE-18 可用 Playwright 脚本 + DOM 断言覆盖（现有 `e2e/` 已有 Playwright 基建与多视口截图能力，可直接扩展）。
2. **半自动**：UE-09、UE-10~14 需构造状态后截图存档，人工复核一次文案口径。
3. **判定口径**：P0 任一不通过 → 整体不通过；P1 不通过项需登记；P2 可进后续迭代。
