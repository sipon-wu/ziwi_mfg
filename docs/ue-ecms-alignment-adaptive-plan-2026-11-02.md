# 与能碳（ECMS）界面一致 + 多端交互自适应 方案

> 2026-11-02 · 依据：mfg 源码实测 + ECMS 源码逐文件比对（`ziwi_project_dna/frontend`，36 视图）+ 真浏览器三档取证
> 状态：待评审。本文只出方案，不含实现。

---

## 0. 一句话结论

两个诉求要**分开处理**：

| 诉求 | 判断 | 理由 |
|---|---|---|
| 界面元素与 ecms.ziwi.cn 一致 | **该做，且成本很低** | 两边主色已同为 `#0d7377`，差异集中在 11 个令牌值 + 卡片模型，改 3–4 个样式文件即可覆盖全站 |
| 布局形态与 ECMS 一致 | **不能做** | ECMS 是纯桌面后台：固定 200px 侧栏、11 列 `<table>`、`width:440px` 居中弹窗，**零断点、零触屏优化**。照搬会让 mfg 在车间一体机和手持机上直接退化 |

所以方案的主线是：**把 ECMS 的「视觉语言」搬过来，保留 mfg 的「形态系统」**。

## 1. 事实基线（读码实测，非推测）

### 1.1 技术栈与页面模型

| 维度 | mfg（知微智造） | ECMS（知微能碳） |
|---|---|---|
| 框架 | Vue3 + TS + Vite | Vue3（JS）+ Vite |
| UI 库 | **Vant 4** + unplugin 自动注册 | **无**（36 视图手写 scoped CSS） |
| 状态/图表 | Pinia + ECharts | Pinia + ECharts |
| 样式组织 | 6 个 CSS 文件 + `--ziwi-*` 令牌（288 行） | 无 CSS 文件、**无 CSS 变量**，色值硬编码在各自 `<style scoped>` |
| 页面数 | 76 页 | 36 视图 |
| 列表承载 | **52 页用 `van-cell`**（行式），仅 5 页用 `<table>` | **几乎全是 `<table>`**（桌面表格） |
| 卡片承载 | **38 页用 `van-cell-group`**（白底、无边框、无圆角、通栏） | `.section`（白底 + `1px #e8eaed` + `10px` 圆角 + `20px` 内边距） |
| 多端自适应 | **有** W/T/H 三档（`config/formFactor.ts` 唯一真源） | **无**（0 处断点、0 处 `@media`） |
| 弹窗 | `ZiwiFormSheet` 三档变体：W dialog / T drawer / H 全屏页 | 固定 `.modal{width:440px}` 居中 |
| 空/错态 | `ZiwiStateView` 四分类 | 一行灰字 `.empty` |

### 1.2 已经一致的部分（好消息）

- **主色同源**：`#0d7377`（主）/ `#0d9488`（浅）。mfg `--ziwi-primary` 与 ECMS 的 `.btn-primary`、`.kpi-card::before`、图表渐变首色完全相同。
- **字体栈同源**：`-apple-system … 'PingFang SC', 'Microsoft YaHei'`。
- **侧栏配色同源**：`#212529` 底 + `#adb5bd` 文字 + `rgba(255,255,255,.04)` 悬停。
- **骨架同源**：mfg 的 `MainLayout` 与 ECMS 的 `MainLayout` 连 class 名（`.nav-item` `.nav-submenu` `.flyout-item`）都一样，mfg 是在 ECMS 骨架上做了形态系统。

> 结论：这不是"两套设计要合并"，而是"同源设计在 mfg 这边长出了触屏分支后，视觉参数漂了"。对齐成本远低于预期。

### 1.3 视觉差异明细（11 项，全部有源可查）

| # | 元素 | ECMS 实际值 | mfg 现值 | 观感差异 |
|---|---|---|---|---|
| 1 | 页面底色 | `#f0f2f5` | `#f5f6fa`（`--ziwi-bg`） | 灰度不同，mfg 更偏冷 |
| 2 | 卡片边框 | `1px solid #e8eaed` | 无（cell-group 通栏） | **最明显**：ECMS 是独立白卡，mfg 是通栏白块 |
| 3 | 卡片圆角 | `10px` | 无 / `8px`（`--ziwi-radius-lg`） | 同上 |
| 4 | 卡片内边距 | `20px` | cell 12px（`--ziwi-gap-md`） | ECMS 更松 |
| 5 | 卡片标题 | `h3 15px #333` | cell-group title 12px 灰 | 层级感不同 |
| 6 | 主文字色 | `#333` | `#1e293b`（`--ziwi-text-primary`） | mfg 偏冷偏深 |
| 7 | 分割线 | `#f0f0f0` / `#e8eaed` | `#f1f5f9`（`--ziwi-border-light`） | 近似 |
| 8 | 表头底色 | `#f5f7fa`，`#666`，500 | 仅 5 页有 `<table>`，其余无表头概念 | 列表形态不同，非配色问题 |
| 9 | 标签圆角 | `10px`（药丸）+ `2px 9px` | `4px`（`--ziwi-tag-radius`） | mfg 方正，ECMS 圆润 |
| 10 | 弹窗 | `12px` 圆角 / `440px` / `24px` 内边距 | `8px`（`--ziwi-radius-lg`） | mfg 更方 |
| 11 | 侧栏宽 | `200px` / 折叠 `50px` | `220px` / 折叠 `60px` | 折叠态二级弹层定位基准跟着变 |

## 2. 第一部分：界面元素一致（视觉层）

### 2.1 三条硬性"保持不一致"（写进方案，防止后人改回去）

| 项 | ECMS | mfg 必须保持 | 原因 |
|---|---|---|---|
| 可点热区 | `.btn{padding:6px 16px}` ≈ **30px 高**；`.btn-link` 字号 12px | ≥48（裸手）/ ≥56（手套） | 车间一体机与手持机纯触屏，30px 点不中；这是 UE-P0-02 的验收线 |
| 正文字号 | 表格 13px、`.btn-link` 12px | ≥14（`--ziwi-font-size-lg`） | 现场视距 30–80cm，13px 认不出（UE §1.2） |
| 浮层形态 | 固定 `440px` 居中 | W dialog / T drawer / H 全屏页 | 440px 在 412px 宽手持机上会横向溢出 |

> 原则一句话：**颜色、圆角、间距、层次对齐；尺寸、形态、热区按现场。**

### 2.2 落地方式：改 3 个文件，不动 76 个页面

| 文件 | 动作 |
|---|---|
| `styles/ziwi-variables.css` | 按 §1.3 改 8 个色值/尺寸令牌（#1 #3 #5 #6 #7 #9 #10 #11） |
| `styles/vant-overrides.css` | 补 cell-group / tag / dialog / table 的桥接，让 Vant 渲染出 ECMS 的观感 |
| `styles/ziwi-surface.css`（新增，约 40 行） | 暴露 `.ziwi-card` / `.ziwi-card__title` / `.ziwi-toolbar` / `.ziwi-table`，值直接取自 ECMS |
| `styles/ziwi-tokens.gloves.css` | 同步手套档里被改动的 4 个值，避免档位错配 |

改完 `--ziwi-bg`、`--ziwi-tag-radius` 等令牌，**全站 76 页一次性生效**——这正是当初把值收进令牌的收益。

### 2.3 唯一需要动页面的地方：卡片模型

ECMS 的"卡片"是 `.section` 独立白卡；mfg 用 `van-cell-group` 当卡片，是通栏白块。要让 38 个页面都长出 ECMS 的卡片观感，两条路：

| 做法 | 改动面 | 优点 | 缺点 |
|---|---|---|---|
| **A. CSS 兜住**（推荐） | 0 个页面 | 一次生效，零回归风险 | `van-cell-group` 通栏特性与"卡片"语义不符，宽屏上仍会顶到边 |
| B. 逐页换成 `.ziwi-card` | 38 个页面 | 语义正确、宽屏留白自然 | 工作量大，且 38 页都要回归 |

**建议：先 A，把 B 拆进后续批次按模块推进。** 因为 A 已经能解决"看起来不像同一个产品"的问题；B 解决的是"宽屏上排版不合理"，属于 §3 的自适应范畴。

### 2.4 验收口径

不是"值改对了"，而是**并排截图对得上**：
- 取 ECMS `EnergyOverview`（KPI 卡 + section）与 mfg 任一列表页并排，卡片的边框/圆角/内边距/标题字号肉眼不可区分
- 取 ECMS `DeviceProfile`（表格 + 标签 + 搜索框）与 mfg 有 `<table>` 的 5 页并排，标签形状一致
- 弹窗并排：ECMS `.modal` 与 mfg `ZiwiFormSheet` 的 W 档，圆角与内边距一致

## 3. 第二部分：多端交互自适应（W/T/H）

### 3.1 现状盘点：哪些组件有形态分支

| 组件 | 形态分支 | 说明 |
|---|---|---|
| `MainLayout` | ✅ | 桌面侧栏 ↔ H 抽屉；折叠态二级弹层 |
| `ZiwiFormSheet` | ✅ | W dialog / T drawer / H 全屏页（`sheetVariantOf`） |
| `ZiwiConfirmSheet` | ✅ | 危险确认三档 |
| `ZiwiActionBar` | ✅ | 底部主操作条 |
| **`ZiwiSelect`** | ❌ **0 处** | 上一轮实测：三档全为 100% 宽底部浮层（UE §3.2 要求 W 用下拉） |
| **列表页（52 页）** | ❌ | W/T/H 同一套 `van-cell` 行式列表；UE §3.2 要求 W 用表格、H 用卡片流 |
| **筛选/高级检索** | ❌ | UE §3.2 要求 W 常驻筛选栏、H 底部浮层 |
| **详情页** | ❌ | UE §3.2 要求 W 抽屉/双栏、H 全屏页 |
| `ZiwiStateView` / `ZiwiSelectList` / `ZiwiQtyField` / `ZiwiScanField` / `ZiwiCodeText` | ❓ 待核实 | 预计无分支，需逐项确认 |

**这就是当前最大的交付欠账**：骨架（布局/表单/确认/操作条）已有三档，但**承载 80% 信息量的列表页一档都没分**。

### 3.2 三档定义（引用 `config/formFactor.ts`，纯宽度主判据）

```
H: [0,600) ∪ (竖屏 且 [0,768))
T: [600,1024) 横屏 ∪ (竖屏 且 [768,+∞))
W: [1024,+∞) 横屏
```
输入能力（`hasHover`）**不参与判定**，只作 W 档内的悬停增强。1024 归 W。

### 3.3 逐元素形态矩阵（方案核心）

| 元素 | W 宽屏 | T 中屏 | H 手持 | 现状 | 差距 | 优先级 |
|---|---|---|---|---|---|---|
| 主导航 | 固定侧栏 200px，可折叠为 50px 图标条 + 二级弹层 | 同 W | **全屏抽屉**，点遮罩关闭 | 已有 | 宽度按 §1.3 从 220/60 改 200/50 | P1 |
| 数据列表 | 表格：首列冻结、可横向滚动且**显性提示**可滚 | 表格减列（3–4 列）+ 行展开补细节 | **卡片流**：主标识 + 状态 + 关键数值 + 时间 | 三档同为 `van-cell` 行式 | **最大缺口**，52 页 | **P0** |
| 详情 | 右侧抽屉或双栏 | 全屏页 | 全屏页 + 主操作固定底部 | 多为全屏页 | W 缺抽屉 | P1 |
| 新建/编辑表单 | 居中浮层，宽度按视口比例上限 | 右侧抽屉 / 半屏浮层 | 全屏页 + 底部固定主操作 | 已有（ZiwiFormSheet） | 无 | — |
| 枚举选择器 | **下拉浮层**锚定字段下方 + 可选搜索 | 底部浮层 + 搜索框 + 列表 | 底部浮层 + 大行高列表 | 三档同形 | 需补 W 分支 | **P0** |
| 危险确认 | 居中确认浮层 | 底部确认浮层 | 全屏确认页 | 已有 | 无 | — |
| 筛选/高级检索 | **常驻筛选栏** | 折叠面板 | 底部浮层，条件以标签回显 | W 用底部浮层 | 需补 W 常驻 | P1 |
| 主操作 | 内容区右上 / 行内 | 底部条 | 底部条，常驻拇指区 | 已有（ZiwiActionBar） | 无 | — |
| 打印预览 | 全屏页 + 右侧窄操作区 | 同 W | 全屏页 + 底部双按钮 | 已有 | 无 | — |
| 图表（ECharts） | 完整图表 + 图例 + 数据标签 | 减图例、保数据标签 | **单图 + 横向滚动或下钻**，不塞多轴 | 未区分 | 需定 H 降级规则 | P2 |
| 提示/回执 | 角标 toast | toast | 全屏回执或底部条 | 已有（ZiwiReceipt） | 无 | — |

### 3.4 触屏五条容器硬约束（R1–R5，任何一档都不得违反）

| 编号 | 约束 |
|---|---|
| R1 | 浮层/抽屉内若需滚动，**浮层自身是唯一滚动容器**；选择器不得内联进表单流 |
| R2 | 浮层宽度由外层策略决定（视口比例 + 上限），**不得由内容撑开** |
| R3 | 一个语义只允许一组操作按钮；内层自带确认时外层不再给同语义按钮 |
| R4 | 主操作常驻拇指可达区（T/H 固定底部），不随内容滚出 |
| R5 | 悬停只作增强，不得承载唯一信息 |

热区双档：裸手 48×48、手套 56×56（`--ziwi-touch-min` / `--ziwi-touch-danger`）。

### 3.5 改造清单（按优先级）

**P0 — 不补就等于"自适应只做了一半"**

1. **`ZiwiSelect` 补 W 档下拉分支**
   现状：`formFactor` 出现 0 次，三档都是 100% 宽底部浮层。
   目标：W 档改为锚定字段下方的浮层（宽度跟字段、最多 8 项超出滚动、点外部关闭）。
   影响面：全局组件，`SelectField` 薄壳转发，basics 8 页 + 其他 6 页共用 → 改完需全量回归。
2. **列表页 W 档表格化**
   52 页是最大工作量。建议先做**通用列表容器**（`ZiwiDataList`）：传列定义，内部按档渲染「表格 / 减列表格+行展开 / 卡片流」，页面只提供列定义。否则 52 页各写一套分支必然失控。
   落点：先改造 5 个高频页（工单、收货、出库、检验、库存）验证容器，再批量迁。

**P1 — 观感与可用性**

3. 侧栏 220/60 → 200/50（含折叠态二级弹层定位基准同步）
4. W 档筛选栏常驻、H 档底部浮层 + 条件标签回显
5. 详情页 W 档抽屉/双栏
6. `ZiwiStateView` / `ZiwiScanField` / `ZiwiQtyField` 等逐项核实是否有隐含尺寸假设

**P2 — 打磨**

7. ECharts H 档降级规则（单图、禁多 Y 轴、禁旋转标签）
8. 动效八类（A1–A8）在三档下的档位统一（UE §7）

## 4. 实施路径（四批，每批独立可验收）

| 批次 | 内容 | 影响面 | 验收 |
|---|---|---|---|
| **B1 视觉对齐** | §2.2 的 3 个样式文件 | 全站 76 页一次性变色/变圆角 | 与 ECMS 并排截图，卡片与标签不可区分；UI 契约闸 `inline_style` 不升；24 页 touch_target 仍达标 |
| **B2 选择器三档** | `ZiwiSelect` W 下拉分支 | 14 个使用页 | 三档实测几何：W 锚定字段下方 / T、H 仍底部浮层；键盘 ↑↓/Enter/Esc 三档都可用 |
| **B3 列表容器** | 新增 `ZiwiDataList`，先迁 5 页 | 5 → 52 页 | 三档渲染形态正确；W 横向滚动有显性提示；H 卡片流首屏可辨主标识 |
| **B4 剩余形态** | 筛选栏、详情、图表降级、动效档位 | 按模块 | 逐模块三档截图对照 |

每批都跑：`python scripts/check_ui_contract.py`（`inline_style` 只许降）、`vue-tsc`（改动文件 0 新增错误）、三档浏览器 E2E。

## 5. 风险

| 风险 | 说明 | 对策 |
|---|---|---|
| **R-A 令牌一次性影响 76 页** | 改 `--ziwi-bg` / `--ziwi-tag-radius` 会同时改观感，可能撞上依赖旧值的局部样式 | B1 只改值不改语义；改完用 24 页 touch_target 探针 + 截图抽检；发现局部硬编码色值先记不改 |
| **R-B ECMS 自身没有自适应** | 不能拿 ECMS 当 T/H 参照物；照搬它的"表格 + 440px 弹窗"会在手持机上溢出 | T/H 以 mfg 自己的 UE 规格 §3.2 为准，ECMS 只提供视觉参数 |
| **R-C 52 页列表表格化是最大工作量** | 若逐页手写分支，必然出现 52 种写法 | 强制走 `ZiwiDataList` 容器，禁止页面自写断点 |
| **R-D ECMS 无令牌，未来它自己会漂** | ECMS 色值硬编码在 36 个 `<style scoped>` 里，改一次要改 36 处 | 建议同步向 ECMS 侧提出「抽出令牌」，否则本次对齐是一次性快照，半年后又会分叉 |

## 6. 开放问题（需拍板）

1. **「界面元素一致」的范围**：全站 76 页（含改侧栏宽度、页面底色这类会整体变观感的项），还是只对齐"卡片/标签/按钮/弹窗"这类元素、页面底色与侧栏宽度保持 mfg 现状？
2. **B1 是否连带把 38 页的 `van-cell-group` 换成真卡片**（§2.3 的做法 B）？还是先用 CSS 兜住、后续按模块推进？
3. **列表 W 档表格化**：是否接受新增 `ZiwiDataList` 容器（页面要改列定义写法的迁移成本），还是只做"减列 + 行展开"不引入表格？
4. **ECMS 侧是否配合抽令牌**？否则 R-D 无解，这次对齐只是快照。
