# 知微云（cloud）质量保障纪律

> 适用范围：cloud（统一登录 IdP / License 授权 / heartbeat）全部前后端改动。
> 制定：2026-07-28。与 school 项目「工作纪律基本法」同一把尺，但 cloud 红线等级更高。

## 0. 定位与风险等级（最高）

- cloud 是**核心能力组件**：统一登录（IdP）、License 授权、heartbeat 全部依赖它。
- **无独立预发布环境**：按 2026-07-28 拍板，不部署独立 staging cloud，采用单一生产 IdP + env claim + CORS `*` 方案；各产品线 staging 直接对接生产 cloud 统一登录。
- 影响面跨多产品线（school / mfg / heartbeat 等）：cloud 故障 = 全线鉴权/授权同时失效。
- **结论**：cloud 质量与安全红线**高于普通业务系统**，采用「无 staging 下的加强验证 + 受控灰度」策略。

## 1. 质量原则

1. **契约先于实现** — 前后端响应结构全局统一（list 也包 `{data:[...]}`），从根消除「裸 list vs 包裹」歧义，禁止前端写兼容 hack 掩盖后端不一致。
2. **错误必须可见** — 所有 4xx（422 数组 / `{message}` / 字符串 detail）统一解析并展示具体原因，**绝不允许吞错误**（如 `.message` 只覆盖半截）。
3. **真浏览器 E2E 必须真跑** — 纳入回归，覆盖：登录 → 创建 → 列表出现 → 故意 422 看原因 → 停用/启用 → 越权用例。
4. **改动完成判据 = 改完 + 真验 + 全回归绿** — 编译过 ≠ 可用，「纸绿」不算 done。
5. **生产改动需明确授权** — 部署前必须在真环境验证。
6. **UI/UE 是一等质量公民** — 不能「能跑就行」；平台级产品须有统一设计语言与信息架构。

## 2. 纪律红线（违规即停）

- 不把「能编译 / 冒烟通过」当「可用」。
- 不在无真浏览器验证下部署前端。
- 不吞错误（`.detail.message` 这类只覆盖半截的解析一律禁止）。
- 不把占位空页当用户功能交付。
- **安全专项**：鉴权必须后端强制（不依赖前端隐藏）；越权用例必须 e2e 覆盖；密钥不入库 / 不明文；`CLOUD_DEV_TOKEN_ENABLED` 默认关、生产永不开。

## 3. cloud 专属更高要求

### 3.1 验证策略（无 staging）
- 本地真浏览器 e2e（含 dev-token 真验签链，本地起 cloud 开发实例取长效 token）；
- 各产品线 staging 对接生产 cloud 统一登录做集成验证；
- 生产部署走受控灰度（观察窗口 + 即时回滚预案）。

### 3.2 安全审计（每次改动必做）
- 全端点越权审计：operator 只能看列表不能改；sales 只看自己工单；super_admin 专属操作后端强制；
- License 授权不可绕过；
- 密钥 / 库走 docker volume 持久化，不进代码、不明文。

### 3.3 发布
- 单次变更最小化 + 保留上一个 dist 快照回滚 + 灰度观察窗口；
- 重大变更（统一登录 / JWT / License）先公告再灰度。

## 4. 本次排期

### 阶段 1：根因修复 + 可置信验证（阻断当前卡点）
- 1.1 后端契约统一：`list_users` / `list_business_lines` / `list_tickets` 裸 list → `{data:[...]}`（治根因）。
- 1.2 前端统一错误拦截器：axios 响应拦截器规范化 `e.userMessage`，Login / Register / Console 全复用。
- 1.3 控制台功能闭环：停用/启用按钮（接 PATCH）、中文角色映射、列表搜索 + 角色筛选、loading / 空态。
- 1.4 补 cloud 真浏览器 e2e（登录 → 创建 → 列表出现 → 故意 422 看原因 → 停用/启用 → 越权用例）。
- 1.5 部署到生产 cloud（需授权）+ 回滚预案。

### 阶段 2：UI/UE redesign
- 2.1 设计语言：品牌色板、Logo、间距/圆角 token、字体（先出高保真原型确认）。
- 2.2 信息架构：侧边导航（账号管理 / 业务线 / License 工单 / 系统）+ 顶栏。
- 2.3 账号管理页重做：表格 + 搜索 + 筛选 + 分页 + 行内操作（停用/启用/删除/重置密码）+ 创建抽屉。
- 2.4 业务线管理页、License 工单页（创建/列表/审批流）—— 接已存在后端端点。
- 2.5 租户自助中心（TenantView）从占位到实质（License 激活 / 账单 / 发票结构）。
- 2.6 统一 loading / 空态 / 错误态组件。
- 2.7 高保真原型先行确认再落地。

## 5. 回归门禁

- cloud e2e 全绿才允许部署。
- 越权用例（operator 改账号、sales 看他人工单）必须覆盖。
- 安全审计项（3.2）逐条勾。
