# 知微 Heartbeat 产品规格（实现状态）

> 本文档以 **当前运行代码为准**（部署于 heartbeat.ziwi.cn，预发布容器已验证）。
> 用途：记录产品功能边界与实现度，作为产品规划与验收基线。
> 配套技术对接细节见 `INTEGRATION.md`。

---

## 1. 产品定位

**heartbeat.ziwi.cn** —— 知微产品家族的「**License 授权管理 + 部署心跳健康监测**」运维控制台。

- 管控对象：mfg（制造）、school（教学）、cloud（IdP）等知微系产品的**授权状态**与**在线部署实例**。
- 使用方：知微内部 **运维 / 销售 / 财务 / 实施** 团队，按角色隔离可见功能。
- 核心价值：集中掌握"谁在用什么版本、授权是否到期、部署是否在线"，并对授权做受控变更 + 全链路审计。

---

## 2. 用户与角色（RBAC）

| 角色 | 中文 | 可见能力 |
|------|------|----------|
| `super_admin` | 超级管理员 | 全部（含用户管理、系统设置） |
| `ops` | 运营 | 仪表盘 / 授权查看+管理 / 部署 / 告警 / 客户 / 审计 |
| `sales` | 销售 | 仪表盘 / 授权查看+管理 / 客户 |
| `finance` | 财务 | 仪表盘 / 授权查看 / 客户 |
| `support` | 实施 | **预留占位**（当前无独立权限，仅可见"实施工作台"占位页） |

**组合式授权**：用户持有"一组角色 + 直接授予的额外权限点"；有效权限 = 各角色权限并集 + 额外直接授权。

**安全机制（已实现并验证）**：
- 末位超管锁：最后一名活跃超级管理员不可被停用 / 删除 / 降权（否则 409）。
- 越权防护：仅 `super_admin` 可授予 `super_admin` 角色（否则 403）。
- 暴力破解防护：同 IP 连续失败达阈值后锁定一段时间。
- 签名会话 Cookie（HMAC-SHA256，8h 过期，HttpOnly，无服务端状态 → 重启/多副本安全）。
- 双审计链：授权变更写 `license_audit`，账号/权限变更写 `admin_audit`（不可否认）。

## 4. 与其它系统的对接边界

- **机器端（各产品部署实例）**：仅调用 `POST /api/v1/heartbeat`，携带 `X-Api-Key`。服务端**不采信客户端自报的 license_status**，授权状态以后台管理员操作为准。
- **管理端（运维/销售/财务）**：Web 后台（服务端渲染），登录后持签名会话 Cookie 操作。
- **无对外事件流 / 状态查询 / 机器清单 API**（当前机器端只"上报"，不被"查询"）。

## 5. 实现度差距（对照早期技术设计稿）

早期 `INTEGRATION.md` 描述的是更完整的机器端对接愿景，当前代码**未实现**以下能力：

| 能力 | 设计稿端点 | 现状 |
|------|-----------|------|
| 部署事件流上报（started / finished / rollback …） | `POST /api/v1/events`、`/batch` | ❌ 未实现 |
| 部署状态轮询 | `GET /api/v1/status` | ❌ 未实现 |
| 机器实例清单 | `GET /api/v1/machines`、`POST /machines/heartbeat` | ❌ 未实现 |
| 机器端 License 激活/评估/刷新 | `/api/v1/license/activate`、`/evaluate`、`/info`、`/refresh` | ❌ 未实现（激活仅限管理员后台手动） |
| 机器端系统设置 | `GET/POST /api/v1/settings` | ❌ 未实现 |
| 管理员端 角色/设置 配置 API | `/api/v1/admin/roles`、`/api/v1/admin/settings` | ❌ 未实现（角色目录为服务常量） |
| 客户独立数据模型与 CRUD | `/api/v1/admin/customers` | ❌ 未实现（客户视图为 License+Deployment 派生） |
| 指标 / 导出（CSV） | `/api/v1/admin/metrics`、`/exports/licenses` | ❌ 未实现 |

> 这些差距为"设计稿领先于实现"，非缺陷。是否按设计稿补齐，取决于产品优先级（见 §7 待决策）。

## 6. 已知问题（建议修复，待拍板）

1. **License 多产品约束缺陷（P1）**
   `License.tenant_id` 当前为**单列唯一**，导致一个租户只能存在 **1 条**授权记录。
   知微同一租户常并行 mfg + school 等多产品，第二次心跳会因唯一约束冲突触发 500。
   **修复方向**：改为 `(tenant_id, product)` 复合唯一，并配套 SQLite 迁移脚本。

2. **公网 `/admin` 路由冲突（P2，需授权）**
   宿主机 nginx 上其它站点的 `/admin` location 与 heartbeat 冲突，公网 `heartbeat.ziwi.cn/admin` 当前返回 404；预发布验证需经 SSH 隧道直连后端 `:8091`。
   **修复方向**：重载宿主机 nginx 或调整 location 优先级（涉及生产 nginx，需用户授权）。

## 7. 待决策（交于用户）

- A. **机器端对接愿景是否落地**：补齐 §5 的事件流/状态查询/机器清单/License 激活等 API，使 heartbeat 从"上报型"升级为"双向管控型"；还是维持当前 MVP 范围、仅修正文档？
- B. **多产品授权模型**：是否现在就修 §6-1 的复合唯一约束（影响存量数据迁移）？
- C. **客户独立模型**：是否需要从"派生视图"升级为独立客户主数据（支撑更丰富的客户/合同管理）？
