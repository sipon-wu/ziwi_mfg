## 2. 报表模拟

### 为什么要「模拟」而不是「打开看一眼」

报表最危险的错不是 500，是**口径悄悄错了但数字看着合理**：

- 曾对所有工序 `SUM(output_qty)`，多工序工单把产量乘上工序数 → 当日全厂显示 **1760**，实际完工 **74**；
- 改成完工口径后，`total_output`（末道工序）与 `total_wip_output`（工序累计）极易混用，两个数都"有出处"却谁也对不上谁。

所以 `e2e/_report_sim.py` 做**跨层交叉验证**：明细合计 = 汇总、日报之和 = 月报、半年 = 六个月之和。任何一层口径串了，三条必有一条断。

### 结果：18 项对账，0 失败

| 项 | 内容 | 结果 |
|---|---|---|
| R1 | 日报：`rows` 五项合计 == 顶层汇总（184 天） | OK |
| R2 | 月报：`rows` 五项合计 == 顶层汇总 + 工单数 | OK |
| R3 | 月报 == 该月日报之和 | OK |
| R4 | 半年三路对齐（日之和 / 月之和） | OK |
| R5 | 休息日零产出 | OK |
| R6 | 完工口径 ≤ 工序流转口径 | OK |
| R7 | 达产率 / 报废率 / 单台工时落在合理区间 | OK |
| R8 | 月报工单数 == 该月日报出现过的不同工单数 | OK |

### 半年账

| 月 | 完工 | 工序流转 | 报废 | 工单 |
|---|---|---|---|---|
| 2026-05 | 118 | 1,598 | 1 | 11 |
| 2026-06 | 132 | 1,892 | 0 | 15 |
| 2026-07 | 147 | 2,107 | 1 | 15 |
| 2026-08 | 144 | 2,064 | 1 | 18 |
| 2026-09 | 133 | 1,973 | 2 | 15 |
| 2026-10 | 98 | 1,418 | 0 | 10 |
| **合计** | **772** | **11,052** | **5** | — |

派生指标：达产率 **96.7%**（772 / 798，分母 = 133 工作日 × 2 台 × 3 张单）、
报废率 **0.64%**、单台工时 **5.67 h**。

> 口径说明：`total_output` 只认末道工序，所以一天 2 台整机会记成
> 定子 2 + 转子 2 + 整机 2 = **6**。分母里的 ×3 就是这件事，不是拍脑袋。

### 模拟暴露的问题（未修，需拍板）

- **人工工时 == 设备机时，逐行相等**。抽查 2026-06-10：`EL030 labor 8.0 / mach 8.0`，
  全部 43 行比例一致 → 半年流水播种时把两列写成了同一个数。报表本身只是求和
  （求和逻辑没错），但页面上「人工工时 4377.68 h」与「设备机时 4377.68 h」并排
  显示同一个数，车间一眼就不信。要改的是**种子数据**，不是报表。

### 报表页重做

`pages/production/ReportView.vue` 从 40 行日报页改为日报/月报双视图：

- 6 张 KPI：完工产出 / 工序流转 / 报废（含报废率）/ 人工工时（含单台）/ 设备机时 / 工单数；
  **两个产出数并排且各自标注口径**，避免被当成同一个数；
- 明细表：工单号 + 产品 + 完工 / 流转 / 报废 / 工时，行高 ≥ 48；
- 当月工作日数取自工厂日历，日均完工 = 完工 ÷ 工作日。**不叫「达产率」**：
  分母是工作日，不是产能目标；产能目标后端还没有出口，硬编码就是假指标。
- 日历未维护时如实显示「日历未维护」，不造 0。
